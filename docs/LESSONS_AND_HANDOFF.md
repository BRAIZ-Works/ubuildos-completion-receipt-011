# Day 10 Lessons and Handoff

## Lessons carried forward

### 1. Documentation is part of the product
A technically working release is not public-ready when README, navigation, methodology, limitations, privacy, security, accessibility, recovery, rights/use, release notes, verification status, links, or lifecycle truth are incomplete.

**Day-11+ rule:** public documentation must be admitted into the build denominator before producer lock, not repaired after deployment.

### 2. Brand continuity is a testable release requirement
Day 10 initially rendered as a generic application even though the prior campaign release established a stronger UBuildOS/BRAIZ public-proof visual system.

**Day-11+ rule:** compare the candidate against the immediately preceding accepted public release before lock. Check headline hierarchy, campaign identifier, accent system, proof chips, panel/table treatment, responsive behavior, and footer/public-proof language.

### 3. Public-projection verification must fail closed
The original v1.0.0 validator could PASS with required integrity evidence deleted.

**Day-11+ rule:** missing manifest/checksum files, population drift, stale lifecycle language, missing required docs, or broken campaign-copy structure must mechanically fail verification.

### 4. Final social artifacts must be real deliverables
A Markdown carousel outline is not the same as a publishable LinkedIn document.

**Day-11+ rule:** produce and render-QA the final carousel PDF before the publication gate. Include accessibility companion and exact post copy in the same release denominator.

### 5. Do not confuse frozen product identity with public-projection successors
The Fresh-IQA-PASS v1.0.1 product remained immutable while documentation/branding projection patches advanced through v1.0.4.

**Day-11+ rule:** keep product subject, public projection, and publication lifecycle identities separate and explicit.

## Day-11 startup carry-forward

Before Day-11 build opens, require:
- prior-day public visual reference readback;
- complete BRAIZ documentation denominator;
- final social-copy + carousel deliverables;
- publication projection manifest/checksum oracle;
- zero stale placeholders/links/status labels;
- two unchanged-candidate producer sweeps;
- Fresh IQA on the exact locked product subject;
- post-IQA public projection reconciliation before publication;
- live GitHub/Pages and LinkedIn readback before terminal closeout.

The goal remains zero avoidable rework without weakening proof.
